# UEBench 0.2.0 安装与发布说明

> 本文件是 **UEBench 0.2.0** 的安装与发布说明。
> 0.1.0 的对应说明已保留为历史材料，不作为本版本的普通用户文档。

## 1. 本版本是什么

- 产品版本：**0.2.0**（唯一版本源：`pyproject.toml` `[project] version`）
- 平台：Windows 10 / 11 x64
- 性质：**Release Candidate（发布候选）**，等待独立验收；**尚未正式发布**
- Reference Standard：`GB 29446—2019《选煤电力消耗限额》`
- 正式标准包：`2026.10-published.3`（48 项标准 / 765 条规则）

0.2.0 相对 0.1.0 的主要变化：

- GB 29446 业务闭环（RS01）、产品生命周期闭环（RS02）、Excel Adapter 闭环（RS03）、
  **Product Golden v1（RS04）**；
- 正式交付的 GB 29446 导入模板由软件**无头确定性生成**，不再需要人工打开界面另存；
- 版本管理改为**单一版本源**，正式发布链不再手工同步版本号；
- 数据库 schema 升级前**自动建立安全备份**；
- 覆盖安装会先清理旧应用载荷，避免旧 `_internal` 残留；
- 单条损坏的历史记录不再影响“评价记录”与首页加载。

## 2. 代码签名状态（重要）

**本版本未进行 Authenticode 代码签名。**

```text
authenticode_signed = false
unsigned_reason     = no_signing_certificate
```

因此：

- Windows 可能显示“未知发布者”，SmartScreen 可能给出警告；
- 企业环境的应用程序控制 / 白名单策略**可能阻止**未签名程序运行；
- 安装前请用 `SHA256SUMS.txt` 核对文件哈希（见 §3）。

> 注意：`initial-standard-package-published.uebench` **内部有 Ed25519 内容签名**，
> 安装标准包时由软件校验。这与 Windows Authenticode 代码签名是**两件不同的事**，
> 不要混淆。

## 3. 交付物与校验

> **关于文件名中的 `-rc-<short7>`**：Release Candidate 阶段的三个应用产物名里带
> `-rc-<short7>`，`<short7>` 是该 Candidate 的 Git 提交短 SHA（前 7 位）。
> 这样两个内容不同的 Candidate 不会都叫 `UEBench-0.2.0-win-x64.zip`，
> 人工测试时可直接从文件名反查精确源码。正式发布（formal release cut）时才去掉该后缀。
> 用哪个名字请看该交付目录里的 `release-build-info.json`（`candidate_id` 字段）。
> 下表同时给出两种形态。

| 文件 | Release Candidate 阶段 | 正式发布 |
|---|---|---|
| 便携版，解压即用 | `UEBench-0.2.0-rc-<short7>-win-x64.zip` | `UEBench-0.2.0-win-x64.zip` |
| 安装程序 | `UEBench-Setup-0.2.0-rc-<short7>-x64.exe` | `UEBench-Setup-0.2.0-x64.exe` |
| 完整源码、测试、脚本与治理文档 | `UEBench-source-0.2.0-rc-<short7>.zip` | `UEBench-source-0.2.0.zip` |

以下文件在两种阶段下名字相同：

| 文件 | 说明 |
|---|---|
| `initial-standard-package-published.uebench` | 正式签名标准包（`2026.10-published.3`，GB 29446 为 `rule_revision 2`） |
| `GB29446选煤电力消耗限额导入模板.xlsx` | GB 29446 导入模板 |
| `payload-manifest.json` | 应用载荷逐文件 SHA256 与整体 `payload_tree_sha256` |
| `release-build-info.json` | 构建信息、Candidate 身份与未签名声明 |

校验方式（把文件名换成该目录里实际的名字）：

```powershell
Get-FileHash .\UEBench-0.2.0-rc-<short7>-win-x64.zip -Algorithm SHA256
# 与 SHA256SUMS.txt 中同一行的值比对
```

或直接运行验收助手（会生成 `验收结果-<时间>.txt`）：

```powershell
.\验收助手.ps1
```

## 4. 安装

### 4.1 便携版（推荐用于快速试用）

解压便携包（`UEBench-0.2.0-rc-<short7>-win-x64.zip`，正式发布时为 `UEBench-0.2.0-win-x64.zip`），双击 `UEBench\UEBench.exe`。

> 请**不要**把新版本解压覆盖到旧版本的 `UEBench` 文件夹上。若此前解压过旧版，
> 请先删除整个旧 `UEBench` 文件夹再解压，避免新旧 `_internal` 混用。

### 4.2 安装程序

运行安装程序（`UEBench-Setup-0.2.0-rc-<short7>-x64.exe`，正式发布时为 `UEBench-Setup-0.2.0-x64.exe`）。默认安装到 `%ProgramFiles%\UEBench`
（非管理员账户可安装到用户目录）。安装向导为简体中文。

## 5. 升级（0.1.0 → 0.2.0）

0.2.0 是**唯一承诺**支持从上一正式版升级的版本。

1. 直接运行 0.2.0 安装程序覆盖安装即可；
2. 安装程序会先**清理旧的应用载荷**（`_internal`、`UEBench.exe`、`文档`、`模板`），
   再安装新载荷，因此不会残留旧版 DLL 或旧的数据库迁移脚本；
3. **用户数据不会被删除**（见 §6）；
4. 首次以 0.2.0 启动时，如果数据库 schema 需要升级，软件会**自动先建立
   升级前备份**，再执行迁移。

升级前备份位置：`%LOCALAPPDATA%\UEBench\backups\pre-migration-<时间戳>.uebackup`

- 迁移**失败**时：原数据库与备份都保留；
- 迁移**成功**时：备份同样保留（不会自动删除）；
- schema 已经是最新时：**不会**每次启动重复备份。

## 6. 用户数据、卸载与恢复

用户数据目录：`%LOCALAPPDATA%\UEBench\`

```text
uebench.sqlite3          业务数据库
uebench.sqlite3-wal      SQLite WAL
uebench.sqlite3-shm      SQLite 共享内存
standards\               已安装标准与原文
backups\                 备份（含升级前备份）
logs\                    运行日志
imports\                 导入批次
```

- **卸载**会删除程序文件；
- **卸载默认保留**上述用户数据库、备份与业务文件；
- 重新安装后，原有评价记录仍在。

验证流程：安装 → 建立记录 → 卸载 → 数据仍在 → 重新安装 → 记录恢复。

## 7. 标准包与 GB 29446

- 正式标准包 `2026.10-published.3` 随产品内置；**每次正常启动都会执行标准包对账**，
  按已安装包与内置包的版本/身份决定动作：空库安装、完全相同则 NO-OP
  （不重复备份、不重复安装）、旧包自动安全升级、已装更新包不降级、
  同版本或内容冲突不覆盖并明确提示；
- 升级安装前使用现有安全备份能力生成 `pre-package-<时间>.uebackup`；
  安装失败自动回滚，不留半升级状态；历史评价记录及其**规则快照不会被新规则重算**；
- 标准包使用 Ed25519 内容签名，安装时用内置公钥校验；校验失败时不安装、不破坏现有数据；
- GB 29446—2019 的等级判定使用 **full-value exact Decimal 比较**，
  **不执行隐式六位小数修约**（依据 `ECQ-STD-GB29446-001`，状态仍为 `PROVISIONAL`）；
- 若当前加载的 GB 29446 定义缺少正式 r2 所需结构（煤种维度或工艺系数查表行），
  软件会明确提示「标准规则数据不完整或版本不兼容，请更新标准数据后再评价。」并
  **禁止正式计算**，不会再用产品名冒充煤种、也不会给出看似正常但空的工艺下拉框；
- GB 29446 导入模板为 `GB29446选煤电力消耗限额导入模板.xlsx`；
- 菜单「帮助 → 关于 / 诊断信息…」可查看并复制：产品版本、Candidate 身份、
  源码提交（完整 40 位）、内置/已安装标准包 id 与数据版本、标准包 SHA256、
  当前 GB 29446 `rule_revision`、数据库 schema 版本、当前数据目录，
  以及最近一次标准包对账结果（动作 / 原因 / 说明 / 备份路径）。

### 7.1 已知问题（本候选版尚未关闭）

1. **Windows 验收证据不完整**：缺少 Windows 11 实机证据与多显示器 / 多 DPI 实测证据
   （详见 `docs/governance/RS05_EXECUTION_REPORT.md`）。
   验收助手不会因检测到多个显示器就判定跨屏通过，需操作者实测后显式声明。
2. 旧的 `reviewed` 阶段标准库（例如 `2026.08-reviewed.*`）如果与当前正式包存在
   **同标准版本不同内容**，对账会判定为 `conflict` 并明确提示、不覆盖。
   这类库需要由管理员确认后再迁移到正式标准包。
