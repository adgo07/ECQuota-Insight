# 安装与发布说明

> **上下文：本文档描述的是「上一正式发布物 / Previous Release」（`UEBench 0.1.0`）。**
>
> 它是**历史已发布版本**，构建于当前 GB 29446 与 Numeric v1 源码变更之前，**不代表当前 main 源码**，不能用于验证当前源码行为。
> **当前开发源码 / Current Development Source** 以执行时实际 `main` SHA 为准。
> 新的正式发布物将在 RS05（Windows V1 最终验收与发布）通过后形成。当前路线见 [`参考标准开发路线.md`](../参考标准开发路线.md)。

## 上一正式发布物可直接使用的版本

当前同时交付两种 Windows x64 方式：

`UEBench-0.1.0-win-x64.zip`

`UEBench-Setup-0.1.0-x64.exe`

可选择直接运行 ZIP，或运行 Setup.exe 安装。两种方式都不需要安装 Python，也不需要网络连接。第一次启动会在 Windows 的本地应用数据目录创建 SQLite 数据库、日志、备份和标准包目录。

本版已处理 Qt/PySide6 的 ICU 依赖冲突：发布包不再携带开发机上 Poppler 的 `icuuc.dll`，避免出现“无法定位程序输入点 `ucnv_open` 于 Qt6Core.dll”。如果此前解压过旧版运行包，请删除旧的 `UEBench` 文件夹后重新解压本次包，不要混用新旧 `_internal` 文件。

## 校验文件

发布目录中的 `SHA256SUMS.txt` 与运行包放在同一目录。解压前先在 PowerShell 执行：

```powershell
Get-FileHash .\UEBench-0.1.0-win-x64.zip -Algorithm SHA256
```

只有输出值与 `SHA256SUMS.txt` 完全一致时才继续解压。

不懂编程时可在交付目录双击 `验收助手.cmd`。它会自动检查三个不可变文件的哈希、确认表和导入模板是否存在；如果检测到已解压目录中旧版 ICU DLL，也会明确提示删除旧目录，并生成验收结果文本；随后再按提示解压并双击 `UEBench\\UEBench.exe`。

## Inno Setup 安装程序

项目已提供 `packaging/installer.iss` 和 `scripts/build_release.ps1`。在安装 Inno Setup 6 的 Windows 构建机上执行：

```powershell
.\scripts\build_release.ps1
```

本次 Setup.exe 已完成编译；已在项目内独立目录完成静默安装、安装后启动和静默卸载验收。安装后的 UEBench.exe 直接启动成功，未调用 Python，主窗口、SQLite、标准包和日志均正常；卸载后程序文件已移除。首次在普通 Windows 10/11 电脑使用时，仍建议先运行“验收助手”核对文件哈希。

## 正式标准包发布

当前数据目录已完成47项范围、753条当前指标和1项历史标准的结构化录入；753条当前规则已在统一确认表中逐项确认并发布，当前正式包版本为 `2026.09-published.2`，共765条规则（753条当前规则、12条历史规则）。GB 29435-2025的51条规则来源于原文PDF，SHA-256为`7fe37d8710c4639c63fdc47e51afda0de20fa683a0dfd62877f7aa5cfde95f54`，专项复核表记录了页码、条款、表号和王玮于2026-09-09的转正确认。软件按电脑真实日期自动区分当前有效、历史和未来标准；GB 29435-2025实施日期为2027-01-01，当前只能预览。旧标准和未来标准可手动选择，软件会显示相应提示。GB 29141-2012仅用于历史评价，GB 29437-2012和GB 29441-2012已由GB 29141-2024替代且未纳入本包历史规则。若后续标准修订，仍按以下命令生成新的版本：

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe tools\publish_confirmed_rules.py `
  "dist\release\统一标准规则确认表.xlsx" `
  "G:\标准  规范\02_能耗限额_终端产品\单位产品限额\现行强制文本" `
  --output "dist\standard-packages\initial-standard-package-published.uebench" `
  --apply
```

只有在新的确认表逐项完成人工确认后，才允许使用 `--apply`；本次交付的 `2026.09-published.2` 已完成该门槛，可用于当前已实施标准的正式判定。

## 开发基线与历史快照

当前唯一的标准开发入口是 standards/development/scope-63，其中包含63项范围定义；已发布规则和待复核草案分开管理。standards/development/scope-65 仅用于历史对照和回归测试，禁止直接作为发布入口。

新增或替代标准时，先更新 scope-63 的范围文件和定义，再完成原文页码核对、规则确认表和边界测试；确认表未完成前不得把 draft 规则提升为 reviewed，也不得生成正式标准包。具体命令以 README.md 和当前工具的 --help 输出为准。
## 增量标准包

开发端可使用 StandardPackageBuilder.build_incremental() 生成增量包：传入父标准包和完整的目标规则集合，程序会只写入新增或发生变化的规则，并自动写入父包 ID。同一标准版本出现更高 rule_revision 时允许旧修订被替换；没有差异会拒绝生成；真正删除父包已有规则或标准时会拒绝并提示改用完整包。只有勘误变化时也可以生成仅勘误增量包。运行端仍会校验签名、哈希、数据版本、父包是否已安装及安装事务回滚。
