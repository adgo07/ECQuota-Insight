# 统一判定规范

状态：**N01-A 迁移中**。本文件记录 ECQuota 当前 Numeric 原则与逐标准迁移边界；不得把单个 Pilot 的结论自动扩大为全平台已冻结规则。

## 1. 正式判定与显示必须分离

正式数值链遵循：

`原始十进制输入 → Decimal parse → 标准公式计算 → full calculation value → 正式比较 → 等级/结果`

显示链独立为：

`calculation value → display formatting / display rounding`

显示位数不得反向进入正式计算、限值比较或等级判定。

## 2. 不再把全局 ROUND6 视为当然正确的业务规则

历史实现曾统一执行 `ROUND(value, 6)` / `ROUND_HALF_UP` 后再做数值边界比较。该行为现在定义为 **legacy implementation behavior**，不是自动成立的标准依据。

正式规则应按以下优先级确定：

1. 标准原文明文规定修约、小数位、有效数字或舍入方式时，按标准建立 explicit business rounding，并记录来源；
2. 标准未规定时，不得为了兼容旧软件而增加 implicit rounding；
3. display rounding 仅用于 UI、报告和导出。

本次 QZC-N01-A 已核对 GB 29446—2019：表1、表2、5.2 式（1）及附录A未发现要求在等级比较前统一修约 6 位的条文。因此 GB 29446 正式判级采用 Decimal full-value comparison。

## 3. 当前迁移状态

| 范围 | 当前正式实现 | 状态 |
|---|---|---|
| GB 29446—2019 | Decimal full-value comparison；无 implicit ROUND6 | QZC-N01-A 已实现，待独立验收 |
| 其他已实现标准 | 可能仍存在 legacy ROUND6 | 不在 N01-A 中批量迁移；后续必须逐标准核对原文后处理 |
| `Expression.round_places` | 仅在规则显式声明时执行 `ROUND_HALF_UP` | 保留；GB 29446 当前正式规则未使用 |
| UI / report / export 显示 | 可按显示位数格式化 | 不得影响 grade |

因此，代码中保留 legacy ROUND6 helper **不代表** GB 29446 仍使用 ROUND6，也不代表其他标准已经证明 ROUND6 有标准依据。

## 4. GB 29446 breaking behavior

N01-A 采用 `δ = 0.0000004` 验证阈值两侧。以下旧结果属于 intentional numeric behavior change：

| Exact value | Legacy ROUND6 | Full-value |
|---|---|---|
| 5.0000004 | 1级 | 2级 |
| 7.0000004 | 2级 | 3级 |
| 8.5000004 | 3级 | 未达标 |
| 2.0000004 | 1级 | 2级 |
| 3.0000004 | 2级 | 3级 |
| 4.5000004 | 3级 | 未达标 |

旧测试不得静默删除；改变结果的旧期望应作为 legacy/breaking evidence 保留，新正式期望由 N01-A Conformance Vectors 验证。

## 5. 其他既有业务原则

- 指标未满足标准最低等级/限定值时输出“未达标”；缺少必需数据仍为“不完整”，确实不适用仍为“不适用”。
- 企业属性不改变 GB 29446 的指标等级；准入或建设属性提示与等级结论分离。
- authoritative Domain 不接受 Python binary float；正式输入应保持可追溯的十进制语义。
- 历史评价不自动重算，保留当时结果、规则快照和计算轨迹。
- 新 Numeric 语义必须可追溯。GB 29446 新结果的 `grade_comparison` 轨迹记录 `numeric_behavior=ecquota-gb29446-full-value-v2`；旧结果仍保留旧 `ROUND(..., 6)` 轨迹，因此不会伪装为同一算法。
