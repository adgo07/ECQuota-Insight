## 结论

当前项目的分层方向是正确的，适合继续完善 Windows 首版，并为以后增加 Web、Linux、macOS、安卓、鸿蒙等适配器保留空间。现阶段最大的限制不是目录结构，而是标准数据仍有草案和待复核项，以及尚未完成用户目标电脑的现场验收。

## 已验证的结构

| 层 | 当前职责 | 结论 |
|---|---|---|
| domain | 标准模型、Decimal 计算、条件/公式、判级、计算轨迹 | 不依赖 Qt、SQLite、Excel，适合复用 |
| application | 评价、标准选择、导入导出、标准包、备份、审计等用例门面和端口 | 桌面界面通过 ApplicationFacade，后续适配器可复用 |
| infrastructure | SQLite/Alembic、Excel、签名标准包、备份、日志、跨平台数据路径 | 外部技术集中在此层 |
| ui | PySide6 Widgets 展示和收集输入 | 已增加分层边界回归测试 |
| data | 当前已发布规则和运行时标准包内容 | 软件正式计算只使用 published |
| standards/development | Git 保护的 63 项开发基线和 65 项历史对照 | scope-63 是唯一开发入口，scope-65 只用于追溯 |
| work/dist | 可重建中间产物和发布产物 | 不应作为规则的唯一来源 |

## 本轮已处理

1. 原文查看现在按选定标准版本查询，并对候选 PDF 做 SHA-256 匹配；同名旧/新 PDF 共存时不会只按文件名误打开旧文件。
2. 增加了应用层回归测试，覆盖“旧文件同名、正确文件哈希匹配、未来/历史选择模式传递”。
3. 安装发布说明和验收记录已同步为最新隔离安装、启动、卸载结果；仍明确提示需要在用户目标电脑做现场验收。
4. 新增统一开发标准库索引，集中登记63项当前标准和4项归档标准；发布构建会先校验索引，scope-65仅作为历史比较快照。
5. 审计报告新增“原文明确缺级”分类，11条记录均已绑定来源页码/条款/表号，避免把标准中的 `—` 误报成漏录。

## 当前仍需重点处理

1. scope-63 仍有 17 项整体草案；原先的11条缺级提示已逐项对照原文并分类为“原文明确缺级”，不再作为未解释的质量警告。草案标准在确认前仍不得发布或正式评价。
2. 正式包当前为 46 项当前标准、1 项历史标准；3 项 2027-01-01 实施的新标准可手动预览，但当前日期不会默认选中。
3. 已完成本机隔离安装/启动/卸载，尚未在一台真正未安装 Python 的 Windows 10/11 电脑完成“安装、评价、Excel 导出、备份恢复、卸载”全流程。
4. macOS、Linux、安卓、鸿蒙和小程序的安装包尚未制作；当前完成的是核心层和数据路径的预留，不应对外宣称已支持这些平台。
5. NAS/网络升级目前是“扫描并手动安装签名包”；自动发现、下载、回滚和服务器端发布流程仍是后续工作。
6. 标准更新必须继续遵循“原文/修改单 → 规则录入 → 独立复核 → 确认表 → published 标准包 → 回归测试”的顺序，不要直接改 data 中的限额值。

## 建议下一步顺序

- 先用普通 Windows 10/11 无 Python 电脑完成现场验收并保存结果。
- 继续确认剩余17项草案标准；11条原文缺级已归档，不再重复猜填。
- 对新标准或修订建立新的 rule_revision 和标准包版本，保留旧规则快照。
- 在规则数据稳定后再做自动更新服务和其他平台适配，避免多个客户端各自复制判级逻辑。
