# ECQuota-Insight 源码使用说明

> 当前产品目标：下一正式版完整支持 GB 29446—2019。总体路线见 [`参考标准开发路线.md`](../参考标准开发路线.md)。
> 本文中的历史盘符、数量与发布记录仅为当时记录；当前开发源码以实际 `main` SHA 为准。

## 环境与启动

Windows 10/11 x64，Python 3.13；程序包名仍为uebench。

```powershell
git clone https://github.com/adgo07/ECQuota-Insight.git
Set-Location ECQuota-Insight
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uebench.main
```

标准库随软件版本配套（内置并自动对账），**开发与测试不需要手工安装任何标准包，也不需要包内 PDF**；标准原文通过已登记的官方网页查看（全国标准信息公共服务平台，运行时不做检索/抓取）。本仓库不上传标准原文、签名私钥、运行数据库或旧版 EXE；公共验证密钥不是私钥。

## 目录

- src/uebench/domain：正式Decimal计算；application：应用用例；infrastructure：数据库、Excel与签名包；ui：Qt界面。
- data：正式规则；standards/development/scope-63：唯一开发基线，scope-65仅供历史对照。
- tests：回归测试；tools/scripts：校验及发布工具；docs：规范、操作说明及历史记录。

## 测试

纯源码即可跑全量套件（**不再需要本机旧 ZIP，也不用排除任何冻结包测试**）：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp work/pytest-full
```

专项 Gate 与全量套件的分工（CI 与本地一致）：

- Frozen Numeric v1 Conformance、N01-A vectors、Excel/openpyxl 入口探针 → 各自专项 workflow；
- literal full suite → 只由 `Pull Request Gate` 严格执行一次；
- release Source Gate（版本一致性 / 源码卫生 / Candidate 身份 / 构建溯源）→ 源码树层面即可判定，随全量套件与 Candidate 一起跑。

## 构建与发布

正式 Candidate 只有一个构建入口：

```powershell
.\scripts\build_candidate.ps1 -SourceCommit (git rev-parse HEAD)
```

它自己完成：版本一致性 Gate → Development-manifest Gate → **严格全量测试** → PyInstaller 载荷 → 打包后自检 → 溯源写入 → SHA256SUMS → `ACTIVE-CANDIDATE.json` → **Artifact Gate**（`tests/test_release_artifacts.py`，由脚本设置 `UEBENCH_ARTIFACT_DIR`）。任一步失败即整体失败。

CI 上由 `Windows Release Candidate` workflow 在明确需要发布/验收时**手动触发**（`workflow_dispatch`）；普通 PR 不再触发完整候选构建。`scripts/build_release.ps1` 与 `scripts/sync_release.ps1` 已弃用，只保留为历史排查工具，不再是正式发布路径。

- **源码权威 = Git exact commit / release tag**（`git rev-parse HEAD` 或发布标签）。`UEBench-source-*.zip` 只是归档/开发辅助产物，不作为普通用户的正式交付资产，也不承诺“脱离 Git 也能完全重建”。
- 正式用户发布资产：安装程序、便携 ZIP、`SHA256SUMS.txt` 与发布/使用说明。
- 构建依赖按 `requirements.lock` 锁定；安装器编译需要 Inno Setup。签名私钥由维护者离线保管，不应提交到 GitHub。

## 验收边界

GB29446新建页面源码已PASS：12个等级边界、临界值、中文异常提示、正数输入、煤种工艺联动、只读k、核算周期、旧结果清除和保存均有测试。普通页面不含企业属性、单一煤种工艺确认及合规主结论。

标准库规则已完成结构化扫描（无缺项及边界偏差），但不代表其他标准均已完成现场业务验收；0.2.0 的正式评价范围只有 GB 29446—2019。新版 EXE、安装包与独立公式 Excel 尚未同步完成最新口径验收。标准原文查看已收敛为“打开已登记官方网页”，不再随软件分发 PDF。

历史文档盘符、数量与发布记录有日期背景。GB29446专用页面按用户最新要求显示“超出3级”，覆盖早期规范中的“未达标”措辞。

**等级判定口径（当前 / 历史）：**

- **当前口径**：等级比较使用 Decimal **full-value exact comparison**，不执行全局 ROUND6；企业属性填写与否不改变 GB 29446 指标等级。
- **历史口径（已废止）**：早期规范曾要求数值边界两侧先 `ROUND(value, 6)`（`ROUND_HALF_UP`）再比较；该无依据全局 ROUND6 已由 Numeric Contract v1 Full Adoption 移除，`D-ECQ-001` 已关闭。
- **当前权威来源**：`platform-lock.json`（locked SHA）、`docs/统一判定规范.md`、`docs/governance/NUMERIC_V1_ADOPTION_REPORT.md`。
