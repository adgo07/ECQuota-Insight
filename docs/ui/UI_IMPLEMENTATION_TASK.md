## 2 第一阶段 形成真实 Qt 共同样板

先完成以下可运行页面，并保留已有业务连线：

1. 轻量视觉参数与公共控件样式：原始青舟 LOGO、统一 SVG 动作图标、浅蓝侧栏、主次按钮、字体、留白、表格可读性。
2. 首页无侧栏，标准入口优先，设置独立；五入口中导入与系数库禁用；最近记录来自真实数据，有空状态/失败状态。
3. 业务侧栏持续存在；入口命名统一“新建对标”“对标记录”；详情保留对应导航上下文，消除依赖旧固定页索引的跳页风险。
4. 标准库固定五列与唯一标准状态筛选；编号、名称进入同一个独立详情；连续三分区，无详情页签。选煤、水泥映射已确认但未支持、其他未确认三态必须正确；不从旧未验规则展示限值。
5. 选煤单页表单与结果按方案布局；真实候选、工艺联动、自动 k、输入校验、计算/自动记录/Word 连线正常；输入变化旧结果失效，导航切换保留当前输入。

完成后运行相应定向测试，生成少量真实 Qt 样板截图（至少首页、标准列表/详情、选煤表单与结果），说明截图环境、尺寸、数据是否隔离。离屏图可用于布局讨论，但不声称原生 Windows DPI 验收。

在当前执行会话输出阶段摘要，并写到本目录唯一 `UI_IMPLEMENTATION_STATUS.md`：分支、基线/当前提交、改动文件、测试命令与结果、截图绝对路径、已知问题。然后结束本轮执行，等待设计会话检查后的第二阶段指令。这是已授权的设计检查点，不要要求用户逐页签字，不自行宣布最终验收通过。

## 3 第二阶段 完成全部适配

设计会话检查第一阶段后发送继续指令，执行会话在同一分支继续：

1. 对标记录全库搜索、真实 count 与稳定分页，避免只在最近200条或当前页过滤；较早记录可达、损坏行隔离、删除末页回退正确。
2. 独立只读详情，严格“基本信息与结果”“输入数据与计算依据”两个页签。移除普通 UI 重新评价/审计入口，保留必要底层能力和历史数据。
3. 列表和详情摘要来自保存快照，不调用 Calculator、不用当前规则补造缺项；Word 复用现有报告服务，能力不足按真实原因禁用或反馈。
4. 设置保留应用信息、备份恢复、默认折叠高级诊断；恢复仍执行保护与标准库对账。不得恢复手动标准包管理入口。
5. 完成页面上下文、输入法/焦点、长中文与路径、窄窗、空/失败/未开放/旧结果失效等反馈。

记录只读查询可适度扩展 Facade/Repository；不得修改数据库 Schema、改变软删除/记录生命周期或全量加载所有历史大 JSON 到 UI。搜索/排序/总数一致，有可验证的性能边界。显示名称与 enum/机器字段分离。

## 4 设计稿与生产行为的区别

- HTML 只有5条标准样例、1条虚构记录和固定演示结果；生产从本机正式数据服务读取，绝不复制演示企业、时间、输入和结果。
- HTML 部分输入为只读演示、周期候选不完整；生产保留全年、12个月、自定义的完整候选与现有 codec，用户可正常输入。
- HTML “计算”只展开示意；生产必须执行现有正式应用服务并准确显示保存结果，不能增加第二套计算或重复保存。
- 原始 PNG 在 `assets/qingzhou_logo.png`。生产图标应统一到中央/参考仓同义资产，不把示意稿临时图形当冻结图标集；静态复制并记录来源，不跨仓运行依赖。
- 标准库支持标签、映射确认、原文链接分别使用现有服务；官方链接未登记时禁用，不由前端猜测网址。
- 正式功能需保留真实页面上下文恢复；HTML 的简化跳转不构成放宽该要求。
