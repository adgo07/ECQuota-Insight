能耗限额软件 UI 设计方案 V1

日期：2026-10-26。适用产品：单位产品能耗限额评价软件（ECQuota-Insight）。

本方案将现有 Windows 桌面软件调整为青舟统一视觉与操作方式，重点改善标准查找、选煤数据录入、结果阅读和历史记录访问。采用浅蓝业务侧栏、标准优先的无侧栏首页、独立标准详情和两页签记录详情；GB 29446—2019 保持单页对标，计算成功后沿用现有自动生成记录的流程。

交付为设计方案及配套 HTML 阅读与交互示意，不是已实施的软件版本。HTML 中的企业、记录、输入和结果是演示数据，不接入用户数据库；正式界面仍在现有 PySide6 内实现。

4 页面导航与用户路径

启动 → 首页（无侧栏）
       ├ 标准库 → 标准详情 → 按此标准对标 → 新建对标
       ├ 新建对标 → 填写 → 计算并判级 → 自动生成记录 → 查看记录
       ├ 表格导入（禁用）
       ├ 对标记录 → 对标记录详情 → 导出 Word（满足现有条件）
       ├ 折标系数库（禁用）
       └ 设置（独立入口）

业务侧栏：首页 → 标准库 → 新建对标 → 表格导入 → 对标记录 → 折标系数库
底部独立：设置

首页设置进入带侧栏设置页，是本方案对中央 OPEN-05 的推荐选择。记录详情采用业务壳内独立页面，同样属于本轮承载设计选择。

列表到详情保留关键词、筛选、页码、选中行和滚动位置；新打开详情从顶部开始，返回恢复上下文。标准详情仍选中“标准库”，记录详情仍选中“对标记录”。页面间切换保留本次运行中的表单输入，不新增跨启动草稿或“继续项目”。

业务侧栏的禁用项仍可辨认，并在文字旁显示“暂未开放”；不得仅靠鼠标悬停说明。首页卡片和侧栏使用同一开放状态，键盘也不能进入禁用流程。

5 逐页设计

5.1 首页

顶部为真实青舟 LOGO、完整产品名及独立设置按钮。中部按“标准库、新建对标、表格导入、对标记录、折标系数库”排列五张任务卡；标准库为深蓝重点卡，宽度约为普通卡的 1.47 倍。禁用卡仍有标题和一句状态说明。

下方只展示真实“最近对标”，建议最近 5～8 条，字段为企业、统计期、标准、核心结果、评价时间和查看。右上“查看全部”进入完整记录。企业未填显示“未填写企业名称”，不生成企业；尚无记录显示“暂无对标记录”，提供“新建对标”。读取失败显示可重试提示，不能显示成空库。

首页不设置虚构 KPI、支持范围长说明、标准包状态墙或空“继续工作”。标准库就绪异常时，在主入口附近显示一条具体状态提示；新建受阻而历史查看、备份仍可使用。

5.2 标准库列表

标题“标准库”。工具条为可清除关键词输入框和“标准状态”下拉；关键词覆盖编号、名称、适用对象。搜索不要求再次点击按钮，不增加年份、软件支持或映射状态筛选。

固定列为：标准编号｜标准名称｜标准状态｜实施日期｜软件支持。建议内容区 100% 分配为 17% / 35% / 14% / 13% / 21%，列宽可调整；以完整名称和支持状态可读为准，不截断关键含义。编号、名称使用同样的详情动作，Enter/双击也进入详情，不再双击直接打开外部网页。

状态筛选优先复用现有显示口径：“全部、当前有效、尚未实施、历史/已替代、待确认”。“待确认”沿用本仓目录状态投影，不当作业务映射批准状态；不新造公共枚举。本机已存在的历史目录可通过该状态筛选访问，不改变标准效力或正式支持范围。

软件支持沿用“已纳入正式评价范围 / 尚未纳入正式评价范围”。一条标准映射获批，只影响详情中的映射说明，不将第五列升级成可评价。

输入中文时保留预编辑、光标和焦点。可用约 200ms 去抖刷新结果，但不能每输入一个字重新创建搜索框。候选建议属于后续增强，基础版先保证任意词包含检索和筛选稳定。

5.3 标准详情

顶部左侧“返回标准库”，标题显示标准编号与名称；右侧次操作“查看标准原文”，主操作“按此标准对标”。主操作必须同时满足支持范围、适用版本及应用就绪条件，未知标准不可回落到选煤标准。

正文严格按三个连续分区组织，不设页签：

  1. 基本信息：编号、名称、标准状态、实施日期，及本仓已有的业务映射确认说明。映射批准与软件接入状态分别说明；软件支持仍在列表第五列表达，不新增独立支持范围区。
  2. 适用范围：展示已有可信范围文本；尚未整理时如实显示“适用范围待整理”。不在此加入“软件支持范围”。
  3. 标准要求：选煤显示炼焦煤/动力煤的三级上限、指标单位、简短统计范围和必要依据；详情默认可读，长的附录表可以在本分区内折叠展开。水泥与其他未正式支持标准不展示旧工程定义的产品/工序、指标、单位和限值表，沿用现有明确说明。

不显示发布单位、标准关系、单独来源专区或底层规则列表。原文入口只调用已登记的全国标准信息公共服务平台地址；未登记时禁用并显示“官方来源地址尚未登记”，离线打不开时说明原因，不临时搜索、不改为要求导入 PDF。[S1][S4][S5]

5.4 新建对标

采用单页，页面标题“新建对标”。标准摘要紧靠标题，完整显示“GB 29446—2019 选煤电力消耗限额”。当前只有一个正式支持项，采用只读标准值；未来开放多个标准时再启用现有可搜索选择器，未知输入不能自动绑定标准。

分区 字段及控件 规则
基本信息 企业名称（可选）文本框；统计期下拉，自定义时就近显示文本框 延续“全年、1月～12月、自定义”的既有候选和历史编码；评价日期仍自动取当日，不新增必填企业或隐藏的默认年份规则
业务数据 选煤企业类型：炼焦煤/动力煤并排单选 仅改变控件表达，仍绑定原稳定值；不将其改称企业建设属性
业务数据 选煤工艺类型：完整名称下拉，可含关键字匹配 按企业类型联动有效条目；采用原有选取与自动匹配机制，k 更新后立即可见，不静默保留不相容工艺
业务数据 选煤工艺类型折算系数 k 只读值＋“来源：附录A 表A.1”；不可手改，不访问“折标系数库”
业务数据 统计期内选煤电力消耗量 E_d，kW·h；统计期内入选原煤量 m，t 两个宽输入框；保留十进制文本与现有解析规则，单位紧邻标签；不增加无依据的范围上限或两位小数输入限制
数据检查与计算 就近错误及简短问题汇总；“计算并判级”主按钮 输入不足时可点击以定位问题；计算过程防重复提交，业务就绪受阻时禁用并说明原因
结果 选煤电力单耗、等级、简短判级依据、保存状态及后续操作 使用共享 ReportView；结果来自正式服务，不在 Widget 内重新计算

宽窗下，企业与统计期、两个统计量各占一行的两列；企业类型、工艺及 k 保持上下关联，工艺长名称可占整行。窄窗自动改为单列，单位和专业名称不省略。不开八类目录、多工序空树或“基本信息→下一步”的强制向导。

统计范围说明保持默认折叠，展开后写明原煤输送至选煤厂到选煤产品运输出选煤厂，以及选煤、机修、照明、化验室等用电和相关线路、变压器损失。正文不增加企业建设属性、单一煤种工艺确认、合规主结论、备注或项目字段。

计算与结果状态

状态 显示与动作
未计算 结果区简短显示“填写数据后计算”，不展示 0、等级或演示值
校验未通过 错误贴近具体字段；点击问题汇总定位；不清空用户输入，不让旧结果继续有效
正在计算 按钮显示“正在计算…”并临时禁用，防重复执行；不伪造进度百分比
计算成功且服务已保存 显示“已生成对标记录”；主操作转为“查看对标记录”，次操作“导出 Word 报告”
输入变化 清除/失效当前结果及旧导出关联，提示“数据已修改，请重新计算”；历史正式记录不变
再次主动计算 明示“重新计算将生成新记录”，沿用既有创建行为；不把查看按钮接到计算服务
已保存但展示失败 明示“记录已保存，结果暂未显示”，提供查看记录；不诱导重复点击计算
服务失败或返回不完整 以真实服务返回决定是否存在记录和可否导出，分别显示“未完成计算”“未形成有效等级”等，不一概声称未保存或保存成功

D02 提示采用“请输入大于 0 的电力消耗量/入选原煤量（软件防误录校验）”，不能写成标准明文要求。选煤结果仅使用 1级、2级、3级、未达3级及既有异常状态；“未达3级”不是第四等级或“不合规”。

HTML 示例使用批准映射 §12.1 的演示组合：选煤企业类型为炼焦煤，选煤工艺类型为“重介、浮选联合”，k=0.83，E_d=8,000,000 kW·h，m=1,000,000 t，选煤电力单耗 6.64 kW·h/t，2级。显示两位小数仅用于示意；正式比较不受显示修约影响，临界值需要保留完整计算值及判级说明。

5.5 对标记录列表

顶部为关键词输入、“结果状态”筛选和次级刷新动作。关键词涵盖已有企业、标准和可读取的历史业务文本；状态采用实际结果及“记录损坏”等展示状态，不新建业务枚举。不得在最近 200 条的客户端截取结果上宣称已搜索全部记录。

推荐列：企业名称｜统计期｜标准｜核心结果｜结果状态｜评价时间｜操作。核心结果为“数值＋单位”，结果状态单独显示等级/异常；评价时间按操作系统本地时区精确到秒。无统计期的旧记录显示“未记录”，不能用当日年份补齐；既有周期兼容解码仍保留，但界面不把缺字段伪装成用户曾填写的值。

默认每页 20 条，支持上/下一页、总条数与当前页；查询范围覆盖全部未删除记录，稳定排序采用时间降序并以记录 ID 打破同秒并列。搜索/筛选变化回第 1 页，查看详情再返回恢复原页。删除末页最后一条时回退到有效页。损坏记录仍占真实列表位置，并有明确提示，不阻断其他记录。

“查看”为行内动作，删除作为选中记录的次级危险动作，明确对象并默认取消。移除普通记录页的“基于此记录重新评价”，不删除底层历史数据或重算 API。新建只能从新建入口或标准详情开始。[S1 A-10、A-11]

5.6 对标记录详情

保留业务侧栏和左上“返回对标记录”。标题用可读企业名/标准，未填企业时使用“对标记录详情”。右上只有满足当前报告能力的“导出 Word 报告”和必要的原文查看次操作。

严格两个页签：

页签 内容
基本信息与结果 企业、统计期、标准、评价日期/时间、核心结果与等级、三级上限及简明判级依据；注明这是保存时结果
输入数据与计算依据 企业类型、工艺、E_d、m、k、计算式/代入说明、统计范围和必要标准条款；均从保存时请求、结果及规则快照读取

不设第三页签、审计详情、编辑、复制重算、保存草稿或嵌套页签。底层追溯继续保留；面向技术支持的已有诊断仍在设置高级区，不搬进普通记录详情。

导出继续调用 get_report_view(record_id) 和现有 Word 服务，不改历史报告的数值与依据。老记录缺少必要数据时说明无法导出的具体条件，不从当前规则补造内容；是否能导出由服务判断，不能只看标准号。

5.7 表格导入与折标系数库

本轮仅设计两个可见禁用入口，不新建可操作空页面。禁用卡显示“暂未开放”，侧栏同样展示；无“下载模板”“上传文件”“添加系数”等可执行动作。

未来导入获准后采用“模板与说明、选择文件、数据检查与预览、处理结果”四区域，但文件格式、计算和记录流程届时单独按批准范围确定。当前方案不产生新版工作簿，也不复制 GHG 项目保存流程。

5.8 设置与系统反馈

沿用现有“应用信息 → 数据与备份 → 高级”的结构。应用信息显示真实软件版本、配套标准库版本、可换行复制的数据路径。数据与备份保留“创建备份”“恢复备份”；恢复前明确“将替换当前数据，软件会先创建恢复前保护”，默认取消，执行后保留现有即时标准库对账和就绪检查。

高级默认折叠，保留打开数据目录、查看/复制诊断。标准包 ID、SHA、数据库版本和对账详情不出现在首页或普通表单。不新增主题、账号、云同步、导出目录设置或手动标准包安装入口。

6 搜索与异常反馈

场景 页面反馈 数据处理
无匹配标准/记录 “没有匹配结果”，保留关键词，提供清空筛选 不清空原数据
目录或记录读取失败 显示失败原因的用户版及“重试” 不以“共0条”替代失败
标准库尚未就绪 明确当前无法新建；历史记录和备份仍可访问 保留 Application readiness gate
工艺没有有效系数 指明所选工艺缺少可用依据，阻止有效计算 不默认 k=1、不平均、不插值
原文地址未登记/无法打开 分别显示未登记与暂时打不开 不影响已支持本地计算
单条记录损坏 列表保留该行并说明“记录损坏” 其余记录继续访问，不等同于已删除
导出失败或取消 区分失败与用户取消，原记录仍可查看 不假报成功、不重算

按钮具备 hover、pressed、focus、disabled 状态。输入支持 Tab 顺序，Esc 关闭候选弹层而不清空表单，Enter 在列表执行查看。列表检索与业务值确认分离，普通切换、折叠、增加/删除不会无故跳到页顶；仅主动定位错误才滚到错误字段。

7 窗口与 DPI 适配

保留当前最低窗口基准 1180×760，设计主对照 1440×900，另可使用附件 1440×1000 对比家族页面。尺寸指客户区/逻辑布局基准，实测需注明窗口边框和系统缩放，不能混算。

可用内容宽度 布局调整
约 1100 以上 首页五卡一排；标准卡适当加宽；业务表单两列
约 850～1100 首页按最小卡宽自然换行，标准卡仍在最前；业务表单视长标签换行为单列
更窄的有效布局空间 各表单块单列；页级按钮允许换行；标准和记录宽表仅在表格区域横向滚动

在当前最低窗宽，242 侧栏仍可保留，但要减小外边距，避免长工艺名压缩输入框。记录列表优先两行单元格；不得缩小字体强塞七列。125% 或 150% 原生 Windows 缩放至少抽查一个实际可用环境，检查长中文、下标、下拉弹层、焦点框和底部主动作；HTML 或离屏 Qt 不替代该检查。
