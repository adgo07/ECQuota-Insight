# UEBench 0.2.0 交付清单

> 本清单对应 **UEBench 0.2.0 Release Candidate**。
> 0.1.0 的交付清单已保留为历史材料（`docs/交付清单.md`），不作为本版本的普通用户文档。

- 产品版本：**0.2.0**（唯一版本源 `pyproject.toml`）
- 正式标准包：`2026.10-published.4`（48 项标准 / 765 条规则；GB 29446 为 `rule_revision 2`；**不含标准原文 PDF**，provenance-only）
- 平台：Windows 10 / 11 x64
- 状态：**Release Candidate**，等待独立验收；**未正式发布**

> **Candidate 身份**：Release Candidate 阶段三个应用产物名带 `-rc-<short7>`
> （`<short7>` = 该 Candidate 的 Git 提交短 SHA），使内容不同的 Candidate 不会同名。
> 实际文件名以本目录的 `release-build-info.json`（`candidate_id` / `source_commit`）
> 与 `ACTIVE-CANDIDATE.json` 为准；正式发布时去掉 `-rc-<short7>`。

## 2. 代码签名

```text
authenticode_signed = false
unsigned_reason     = no_signing_certificate
```

未进行 Authenticode 代码签名。Windows 可能提示“未知发布者”，SmartScreen 可能告警，
企业应用控制策略可能阻止运行。安装前请用 `SHA256SUMS.txt` 核对哈希。

`.uebench` 标准包内部的 Ed25519 内容签名与此**不是同一件事**。

## 3. 不随普通用户 release 交付

- `统一标准规则确认表.xlsx` —— 状态 **`LEGACY_REFERENCE_ONLY`**：
  - 不作为 0.2.0 发布正确性依据；
  - 不作为正式标准包正确性依据；
  - 不是 `audit_release` 的 PASS 条件；
  - 不是 installer 必需内容；
  - 其“同意发布”**不代表**其余 46 个标准已正式验证。
- 0.1.0 的历史文档与验收台账（保留在仓库 `docs/` 作为历史材料）。

## 4. 正式正确性声明的范围

RS05 的正式正确性声明**只针对已完成 Product Golden 的 GB 29446—2019**。
其余 46 项标准仍为 `Reference Standard Product Closure = PARTIAL` 之外的既有状态，
不在本次候选版中声称达到同等成熟度。

## 5. 已知问题

1. **内置正式标准包中的 GB 29446 定义落后于当前源码定义**
   （包内 `rule_revision=1` 且无“煤种”选择维度；当前源码与 RS04 Golden 为 `rule_revision=2`）。
   因此“安装后用 RS04 Golden 重新验证 GB29446”当前**无法通过**。
   详见 `release/standard-packages/PIN.json` 的 `known_gap`。
2. **Windows 验收证据不完整**：缺少 Windows 11 实机证据与多显示器 / 多 DPI 实测证据。

## 6. 校验方式

```powershell
# 1) 核对交付文件哈希
Get-FileHash .\UEBench-0.2.0-rc-<short7>-win-x64.zip -Algorithm SHA256
# 与 SHA256SUMS.txt 同行比对

# 2) 一键验收（生成 验收结果-<时间>.txt）
.\验收助手.ps1
```

### 0.2.0 正式评价范围与标准原文（Phase 7 收口）

- 0.2.0 的**正式评价范围只有 GB 29446—2019《选煤电力消耗限额》**。其他标准可以继续出现在
  标准库中作为目录/参考信息，但**不得**作为正式评价对象，界面显示「尚未纳入正式评价范围」。
  “标准库里有该标准”不等于“软件已正式支持评价”。
- 0.2.0 **不随软件分发、也不在软件数据目录保存标准原文 PDF**；普通界面提供
  「查看标准原文」，点击后打开**全国标准信息公共服务平台**上预先登记的官方页面
  （不进行运行时搜索或抓取）。未登记官方地址的标准，该入口禁用并提示
  「官方来源地址尚未登记」。
- 标准定义中仍保留标准编号、原文文件名与 SHA-256 等**追溯元数据**，但不再分发原文文件本身。
- 评价记录的时间按**操作系统本地时区**显示，精确到秒（数据库仍以 UTC 存储）。
