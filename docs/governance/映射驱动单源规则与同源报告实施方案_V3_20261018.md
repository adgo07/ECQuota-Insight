## 1. 本轮目标与明确边界

1. Excel 暂不实施，以后按真实需求再决定。当前不开发模板、不生成或交付新版工作簿、不开放导入入口、不拆分 Excel Profile。保留现有后台能力、历史样本及其安全回归，解除当前软件交付对 Excel 模板的强制依赖。
2. 标准相关业务术语必须来自现行批准映射。UI、Word 及未来 Excel 不能各自起名、缩写或改写业务含义；特殊情况必须有 Owner 明确特批及采用记录。
3. 三渠道尽量表达相同业务内容：同字段、同单位、同选项、同适用条件、同实际值、同阈值、同等级、同统计边界及解释。允许布局、分页、展开方式不同，不允许出现三套业务定义。
4. 现有几十项标准的规则只作为待重审的遗留工程资料。目录迁移、能计算、旧测试通过、publication_status=published 均不证明其业务正确。后续由用户逐项整理并批准映射，再以该映射重新审查和实现各标准的核算、判定及全部相关内容。
5. 本轮先完成选煤映射采用、单源维护、同源 UI/Word、必要交付整理。其他标准不借清理改公式，不新增正式支持，不开始水泥实现，不修改水泥已冻结映射。

本轮不做：全部标准纠错、全部 UI 重设计、公共规则 DSL、插件系统、服务器、移动端、数据库迁移、全量 qzpack、重写 Git 历史、删除用户记录或备份。

## 4. 术语与展示内容的单一来源

### 4.1 机器表达

运行时不解析映射 Markdown。实施者按批准映射把业务字段、名称、符号、单位、选项、说明、结果名称及条款定位表达为结构化定义；优先复用 StandardDefinition 与现有应用层共享描述，只补实际必要能力。

每个标准相关展示项至少能定位到现行映射版本和章节；允许多个展示项引用同一章节，不要求给批准正文重新编制编号。特批词应记录原词、特批词、原因、适用渠道/范围和批准证据。未取得特批时沿用批准词或标记待定，不由实现者自行决定专业称谓。

“保存”“取消”等通用操作文案不属于标准业务术语；它们沿用现有产品语言规范，不能借此另起指标、分类或结论名称。

### 4.2 共用内容

共享业务视图至少涵盖：标准、评价对象、统计期、输入量及单位、适用工艺、系数、正式单耗、等级阈值、等级结果、统计边界、必要依据和warning。UI 与 Word 从同一视图取值；未来Excel若获准实施，也接入同一描述及视图，不复制业务解释。

选煤采用“选煤企业类型”“选煤工艺类型”“选煤工艺类型折算系数”等映射原词；内部 coal_type、washing_process、process_factor、Grade.NOT_QUALIFIED 保持稳定。

允许 UI 折叠说明、Word 连续排版、Excel 组织表格；隐藏的专业信息应可访问，报告不另创UI中不存在的业务结论。屏幕与报告默认数字格式共用；临界值如5.0000004不得只显示5.00而不给出2级原因。任何显示处理不参与判级。

现有JSON中选煤系数表在计算、显示和直接录入辅助值中重复展开。应以一份参数维护，必要展开由确定性工具生成并校验，不能依靠人工同步。复杂计算继续允许版本化Domain代码，不把全部业务强塞入JSON。

## 5. 唯一机器源与遗留标准隔离

`data/definitions/` 为唯一可编辑机器定义入口。开发、发布、正式评价三个范围明确分离：

- 开发范围可以包含草稿及待重审资料；
- 随软件发布范围由明确清单选择，本轮不因迁移16项草稿自动扩大；
- 正式评价范围仍只有 GB29446—2019；其他目录标准继续不能据此正式评价。

当前核查：data48项、scope-63当前63项、retired4项、scope-65历史65项；data与scope-63共有47项解析后完全一致，签名包48项与data一致。16项开发独有候选迁入后保持draft及原始规则内容；不能用目录迁移给错误规则背书。

data中的GB29141—2012是已随包历史项；不得用retired中的旧副本覆盖，亦不得因“退休”清理删掉随包兼容内容。历史样本只读保留其真实来源，不能由新规则生成器重造旧数据。

开发索引、发布选择、`resources/catalogue`等必要运行副本从唯一源派生。明确它们是生成产物并校验一致性；签名包、安装数据库、历史Rule Snapshot、独立Golden继续保留，不是可反向编辑当前规则的第二入口。

旧writer先查实际消费者，再退役或改为受控生成；不得把可覆盖当前data的工具藏进archive后继续默认可写。scope-65仅保留实际保护迁移/旧schema的最小只读证据；不为清理删除有效测试，不改为缺外部归档就大面积skip。

## 6. 后续逐标准重建流程

旧规则作为技术盘点资料，不作为业务正确性的证明。用户逐项提供/批准新映射后，按既有Stage A/B/C/D流程执行：

1. 锁定现行批准映射和原文来源，区分标准事实、解释、软件决定。
2. 逐项建立新映射与旧字段、公式、系数、适用性、等级、多指标汇总、输入边界、UI/报告的差异清单。
3. 新疑义先进入根台账；已有批准决定通过引用采用，不重复发明审批手续。
4. 设计核算、判定及共同展示描述；复杂算法允许标准专属Calculator，不让UI发明业务。
5. 更新唯一机器源与必要代码，赋予新规则修订；新Golden根据标准/映射独立推导，旧实现只能用于差异对照。
6. 验证关键边界、反例、异常、多渠道一致性及旧记录不漂移，完成该标准正式验收后才扩大支持范围。

“待映射重审”是治理说明，不增加中央支持状态枚举。已有标准支持状态仍只用规定五态。冻结水泥映射原文不动，其Stage B/C/D必须另按真实阶段推进。

## 8. Word结果报告

正式保存成功后的结果页和记录详情提供同一导出服务。报告标题沿用已提出的《GB 29446—2019 选煤电力单耗等级评价报告》，业务词汇仍逐项对照批准映射；必要新增术语须特批。

技术链：record_id → 原记录Request/Result/RuleSnapshot → 平台无关共享业务视图 → Infrastructure DOCX Writer。Writer不调用Engine、不查询当前标准来替换旧规则、不反算缺失中间量。Application只依赖端口与普通数据，不依赖Word/Qt对象。

内容：已有企业/统计期信息、标准、企业类型、工艺、输入与系数、实际单耗、各级阈值和结果、必要统计范围及依据。E_d/e_d使用下标；不嵌入PDF，不生成可重新求值的业务公式字段。不输出未经确认的企业建设属性符合性结论，不强制补填非计算信息。

历史兼容：

- DETAIL记录展示保存的E_d、m、k及单耗，不重新计算；
- DIRECT记录明确是直接录入的单耗，缺失E_d/m不伪造、不反算；
- 有效1/2/3/未达3级均可导出；INCOMPLETE、NOT_APPLICABLE、损坏核心结果不得冒充正式等级报告；
- 旧记录采用当前兼容显示词时，不伪造其采用了新映射；原值、枚举、来源、Rule Snapshot和已生成文件不回写；
- 新增版本元数据需模型兼容，未知历史值保持未知，不能通过模型默认值宣称旧记录采用新映射。

先写临时文件，成功后替换目标。覆盖确认属于普通文件操作；导出失败不破坏已经保存的记录。输出样例覆盖正常、未达3级、精确边界、中文长名称和DIRECT旧记录，真实生成、渲染并查看；Word/WPS实机可用时核验，不可用时明确待验，不把XML检索当排版验收。

## 11. 验收门槛

1. 映射：归档哈希一致；现行入口唯一；冻结水泥和其他标准Issue不丢；所有标准相关词有映射定位或特批。
2. 单源：唯一可编辑定义入口；16项候选未变正式支持；历史随包项保留；生成副本与源一致；发布清单独立且可复现。
3. 数值：选煤6个阈值、12个k、公式及精确比较不变；D02不扩到其他行业；Numeric conformance、N01-A migration evidence、相关domain/import回归与完整套件按适用要求真实执行。
4. 同源：UI与Word对同一保存记录使用同一业务描述和内容投影，分别比较字段名、单位、选项、值、阈值、等级、说明，不只比较最终等级。Excel延期不构造虚假的三渠道验收结果。
5. 历史：禁止Engine及当前标准查询时仍可导出有效快照；DIRECT不造数据；升级前后旧记录字节及业务投影不被改写。
6. Word：正常/边界/未达3级/旧记录/长中文样例内容和布局真实检查；失败不影响保存；重复导出不重新评价。
7. 交付：新规则、新签名包、PIN和安装状态相符；无PDF、无本轮Excel交付工作簿；DOCX功能在自包含环境可用；升级备份、失败回滚、重复启动保护保留。
8. 清理：有价值安全测试不删除或改skip；普通CI不依赖某台电脑归档；未合并映射分支、其他工作树、用户库/备份/密钥不动。

已存在的一条严格PR full-suite链保留。仅在有清楚收益时合并重复专项，不以CI全面重排作为本轮Word前置；必须保留所有适用向量、probe及检查约束。独立验收检查关键反例和真实产物，不重复制造三份大型报告。
